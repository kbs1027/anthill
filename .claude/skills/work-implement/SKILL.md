# 3단계. 구현

사용자가 덧붙인 말: $ARGUMENTS

## 먼저 확인

- `git branch --show-current`가 `worktree-<작업이름>` 꼴인지 본다. 아니면 멈추고 `/work-start`부터 하라고 알린다.
- 작업폴더(`docs/work/` 아래 `-<작업이름>`으로 끝나는 폴더)의 `plan.md`를 읽는다. 없으면 멈추고 `/work-plan`부터 하라고 알린다.
- 계획서 상태가 `확정`이 아니면 코드를 고치지 않는다. 지금 확정하고 진행할지 사용자에게 묻고, 확정한다고 하면 상태를 `확정 (YYYY-MM-DD)`로 바꾼 뒤 진행한다.

## 하는 일

1. **"변경" 작업이면 고치기 전에 "전" 화면부터 캡처한다.** 방금 만든 worktree는 main과 같으므로 지금 띄운 화면이 "전"이다.
   - `.claude/skills/work-e2e/SKILL.md`의 "띄우기"와 "시나리오"를 읽고 따라, 계획서 7절의 표를 `<작업폴더>/e2e.mjs`로 옮긴다. 이번 작업으로 새로 생기는 화면("전 화면도 캡처"가 "아니오")은 `afterOnly: true`로 표시한다.
   - `node <작업폴더>/e2e.mjs before`를 실행해 `shots/before/`에 저장하고, 캡처를 열어 확인한다.
   - 이미 `shots/before/`에 캡처가 있거나, 화면이 없는 작업이거나, "생성" 작업이면 건너뛴다.
2. **확정된 계획서의 "구현 순서"대로 구현한다.** 요청받지 않은 리팩터링이나 기능은 넣지 않는다.
3. **계획과 다르게 가야 하면:** 작은 차이는 그대로 진행하고 끝날 때 알린다(보고서에도 적는다). 화면, 데이터 구조, 범위가 달라지는 차이면 멈추고 사용자에게 알린 뒤 계획서를 고친다.
4. **빌드가 되는지 확인한다.** `bash .claude/skills/work-implement/check-build.sh`를 실행한다. 한쪽만 건드렸으면 뒤에 `backend`나 `frontend`를 붙여 그쪽만 돌려도 된다.

## 끝나면

구현한 것, 계획과 달라진 점(없으면 "없음"), 빌드 결과를 알린다. 다음 단계는 `/work-test`이다.
